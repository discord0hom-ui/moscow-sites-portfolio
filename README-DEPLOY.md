# Портфолио-сайт: как запустить

Одностраничный сайт без сборки и зависимостей: `index.html`, `styles.css`, `app.js`, `site.config.js`.
Открывается двойным щелчком по `index.html`, но для проверки ссылок лучше поднять локальный сервер:

```bash
python -m http.server 8099
# http://127.0.0.1:8099/index.html
```

## Что заполнить перед публикацией

Единственный файл — `site.config.js`:

```js
window.SITE = {
  name: "Имя или название",        // шапка и подвал
  telegram: "username",            // без @, иначе кнопка скрыта
  whatsapp: "79991234567",         // только цифры, иначе кнопка скрыта
  email: "you@example.com",
  github: "https://github.com/username"
};
```

Пустой канал не выводится на сайте — битых ссылок не будет. Пока не заполнены Telegram, WhatsApp и почта,
в блоке контактов остаётся только GitHub.

## Что проверить перед показом клиенту

- Цены в разделе «Цены» — ориентиры, не утверждённый прайс. Заменить на свои.
- Формулировки о сроках и гарантии (30 дней, 50% предоплата) — тоже черновик условий.
- Ссылки на работы ведут на локальные демо: `demo/index.html` (17 концептов). Внешних кейсов нет,
  поэтому блок «Работы» честно помечает всё как демо и шаблоны.

## Публикация

Вариант 1 — GitHub Pages (репозиторий уже настроен на статику):

```bash
git add -A
git commit -m "Портфолио: услуги, работы, процесс, цены, контакты"
git push origin main
```

Затем Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
Сайт будет на `https://<username>.github.io/moscow-sites-portfolio/`.

Вариант 2 — любой статический хостинг (Netlify, Cloudflare Pages, VPS): загрузить корень репозитория.

## Структура

```
index.html        — портфолио (главная)
demo/index.html   — библиотека из 17 демо-сайтов
sites/            — сами демо-сайты
styles.css        — стили портфолио
app.js            — контакты из конфига, появление блоков, шапка
site.config.js    — имя и каналы связи
assets/favicon.svg
```
